Observability

Evidence of runtime behavior

OpenTelemetry is the common instrumentation layer for traces, metrics and logs; operational telemetry is correlated with request, event, model, dataset and deployment identities.

Traces

End-to-end spans across API → planner → retrieval → rerank → model → tools → persistence.

Metrics

Latency p50/p95/p99, throughput, error/timeout rate, queue lag, cache hit ratio, search quality and model costs.

Logs

Structured, redacted, correlated logs with stable event names and explicit severity.

SLOs

Availability, latency, freshness, search quality and event processing objectives with error budgets.

AI telemetry

Model/provider, token usage, latency, tool calls, evaluation score, safety decision and outcome attribution.

Operational loops

Alert → diagnose → proposal → controlled change → verification → rollback if health guard fails.
