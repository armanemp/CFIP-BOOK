Contracts

Interfaces before implementations

HTTP, event and domain contracts are versioned, observable and backward-compatible. Every contract specifies ownership, schema evolution and failure semantics.

HTTP

  • OpenAPI source of truth
  • request-id and correlation-id
  • deadline propagation
  • stable error envelope
  • explicit pagination/cursor semantics

Events

  • CloudEvents-like envelope
  • schema version
  • idempotency key
  • producer timestamp
  • replay and DLQ policy

Domain

  • invariants belong to domain owners
  • state transitions are explicit
  • side effects are transactional/outboxed
  • audit events are mandatory for governed actions

Compatibility policy

Prefer additive changes. Breaking changes require a new major contract, migration plan, compatibility window and evidence that all consumers moved before retirement.
